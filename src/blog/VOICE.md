# Blog voice

Capture from the first posts (`act-orbstack-local-ci`, `amp-orbs-cloud-agents`).
Use this when drafting or editing articles.

## Sound

- Short sentences. Punch where it earns it: "Your Mac is fast. Use it."
- Plain English. Active voice. Cut filler.
- First person when it is real experience ("I use this on Timekeep").
- Practical, not motivational. No enterprise theater, no hype adjectives.
- Light edge is fine. Clever metaphor only if it carries information.

## Structure

- Open with the pain or constraint in 2–4 short paragraphs.
- Name the idea early. Then tools, setup, real commands.
- Ground claims in a real product (Timekeep) when true.
- Prefer concrete lists over abstract claims.
- Explain config line by line when the file is the point (`.actrc`, setup hooks).
- End with a "Bottom line" that restates the loop in one breath.
- Link related posts when the workflow stacks (local CI ↔ cloud agents).

## What to include

- Exact commands people can paste.
- Tool links (official docs / product pages).
- What *not* to do (hosted vs local, orb vs laptop, secrets).
- Honest limits: approval gates, secrets, when human review still wins.

## What to avoid

- Long throat-clearing intros.
- Em dashes. Use a period, colon, or parentheses instead.
- Buzzwords: "leverage", "unlock", "seamless", "game-changer".
- Tutorial bloat that restates docs without a lived shape.
- Passive "it can be seen that" constructions.
- Inventing setup details not present in the repo.

## Orwell checklist (from Timekeep AGENTS.md)

1. No stock metaphor or figure of speech.
2. Prefer short words.
3. Cut words that do no work.
4. Prefer active over passive.
5. Prefer everyday English over jargon.
6. Break any rule before saying something barbarous.
